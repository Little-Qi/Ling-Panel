# 构建与安装环境说明（Windows）

> 记录一次真实故障：**在本会话工作区目录里直接运行安装包，会报 NSIS 临时文件错误，
> 或选「所有用户」时弹「运行方式」账号密码框；把安装包移到普通目录就一切正常。**
> 结论：不是安装包坏了，也不是 UAC 设置或 electron-builder 配置的问题，而是
> **本工作区目录自带沙箱/低完整性策略**。发布给普通用户的安装包不受影响。

## 现象

安装包位于项目目录：

```
<项目>\dist\LingPanel-0.3.7-setup.exe
```

| 操作 | 在本工作区目录 | 复制到 `C:\Installers\` 后 |
| --- | --- | --- |
| 双击安装（默认「仅为我」） | 曾报 `Error writing temporary file. Make sure your temp folder is valid.` | 正常 |
| 选「所有用户」 | 弹「运行方式」账号密码框，安装卡住 | 正常提权安装 |
| 静默 `setup.exe /S` | 退出码 0 但可能没写注册表 | 正常写入 |

## 根因

本工作区目录（`.mimo-sessions\...\<project>`）被会话沙箱标记为**低完整性/受限区域**：

1. 从该目录启动的 exe 会以 **Low 完整性** 运行（Windows 会按文件/目录的
   mandatory label 给进程降权），即使改用计划任务等非沙箱方式启动也一样。
2. Low 完整性进程调用 `GetTempPath` 得到的是 `%TEMP%\Low`；该目录不可写时，
   NSIS 连插件都解不出来，直接弹
   `Error writing temporary file. Make sure your temp folder is valid.`
3. 同样因为进程受限，安装器切「所有用户」时提权请求无法静默完成，
   在 UAC 关闭的机器上退化成旧的「运行方式」凭据框。

### 验证记录（同一份 exe，只改位置）

| 位置 | 启动方式 | 进程完整性 | 结果 |
| --- | --- | --- | --- |
| `C:\` | 计划任务 | Medium/High | 正常 |
| 工作区 `dist\` | 计划任务（非沙箱） | **Low** | 写不了 `C:\`，无输出 |
| 工作区文件执行 `icacls /setintegritylevel M` 后 | 计划任务 | Medium | 普通安装恢复正常 |
| 工作区（Low 状态） | 双击 | **Low** | NSIS 临时文件错误 |

与之对照：0.3.6 于 2026-10-09 在本机（UAC 已关闭）以 per-machine 方式安装成功，
说明 **UAC 关闭本身不影响安装**；差异只在“从哪个目录运行”。

## 已做的工程化处理

| 位置 | 处理 |
| --- | --- |
| `scripts/build-env.js` | 构建使用项目内 `.build-temp` 作为 TEMP/TMP，避开 `%TEMP%\Low`；同时确保 `%TEMP%\Low` 存在并显式设为 **Low 完整性**（低权限安装器可写） |
| `scripts/check-installer.js` | 检查安装包是否残缺（< 20 MB 直接失败）以及 blockmap 是否齐全 |
| `package.json` | `build:win` 串联上述体检；NSIS 保持 assisted 模式（可选「仅为我 / 所有用户」，覆盖升级沿用旧安装位置） |

**不要给 `dist` 里的产物打 Medium 完整性标签。** 本项目里的 `7za.exe`、`makensis.exe`
在工作区中会以低完整性运行；把产物标成 Medium 后，下一次构建无法覆盖旧文件
（7-Zip 报 `System ERROR: 拒绝访问`）。所以真正的修法是让低完整性安装器有可写的
`%TEMP%\Low`，而不是给产物提权。

注：**「所有用户」的提权仍然会被目录策略拦**（弹「运行方式」账号密码框）——
这不是构建脚本能解除的；普通安装已经可以在项目 `dist` 里直接运行。

## 规范

1. 普通安装（「仅为我」）可以直接在 `dist` 里双击；**要测「所有用户」，先把安装包复制到
   项目外的普通目录**（如 `C:\Installers\`）再运行。
2. 在本目录遇到以下症状，先怀疑目录策略，复制出去重试：
   - `Error writing temporary file. Make sure your temp folder is valid.`
   - 选「所有用户」弹「运行方式」账号密码框
   - 静默安装退出码 0 但注册表/快捷方式没变化
3. 发布产物本身没有问题：用户在普通目录运行、或从 Releases 下载后安装都正常。
4. 判断是不是目录问题的最快方法：把同一个 exe 复制到 `C:\` 下再运行，对比行为。

## 相关历史误判（避免重复踩）

- ❌ “UAC 被关了导致安装失败”——UAC 自 2026-02-03 起就是关的，0.3.6 在同样状态下安装成功。
- ❌ “per-machine 在这台机器上不可用”——从普通目录运行完全正常。
- ❌ “改成 per-user 就能绕开”——能绕开「所有用户」，但普通安装仍会踩 `%TEMP%\Low`；
  而且丢掉了 0.3.6 已有的「仅为我 / 所有用户」选择页和覆盖升级体验。
- ✅ 真正原因：**安装包所在目录**的低完整性/受限策略。
